Open data

このサイトに掲載している情報は、すべて以下のエンドポイントから来ています。すべて認証なしで公開されているので、 curl や iCalendar アプリで誰でも独立検証できます。

Validator 状態

ノード本体の identity・stake・uptime・bootstrap 状態をライブで返します。

validator.json

GET · JSON

NodeID・self-stake・uptime%・P/X/C-Chain bootstrap 状態。トップページの status カードはここから読んでいます。

URL
/api/validator.json
更新
5 分ごと(scripts/node-info.sh がローカル metalgo + canonical P-Chain RPC から書き出し)
スキーマ
ファイル先頭の _comment に各フィールドの導出ルールを記載
リクエスト例 
curl -s https://metal.freedom-yield.com/api/validator.json | jq

Uptime & 実績

監査トレース。直近 90 日分の日次サンプル + 期間終了済 cycle の累積履歴(年間 ~12 件で増えます)。

uptime-recent.json

GET · JSON

直近 90 日の日次 uptime サンプル(observed-at / uptime% / peer 数 / bootstrap / 期間境界)。

URL
/api/uptime-recent.json
更新
毎日 09:10 JST
保持期間
rolling 90 日。それより古いものは下の cycles ファイルに集約
リクエスト例 
curl -s https://metal.freedom-yield.com/api/uptime-recent.json | jq '.entries[0]'

uptime-cycles.json

GET · JSON

各 validation 期間を 1 行として記録: 期間境界の on-chain タイムスタンプ、最終 uptime%、tx ID、explorer URL(独立 audit 用)。長期積み上がる record です。

URL
/api/uptime-cycles.json
更新
cycle クローズ時(現フェーズでは約月 1 回)
監査
各行に explorer.metalblockchain.org 上の tx URL を含むので、誰でも tx 検証できます
リクエスト例 
curl -s https://metal.freedom-yield.com/api/uptime-cycles.json | jq '.cycles | length'

incidents.json

GET · JSON

運用上のインシデントログ。各 entry: id / ISO 8601 date / severity (info|minor|major|critical) / title / summary / impact / resolution。空配列 = 隠してるのではなく、本当にインシデント無しという意味です。

URL
/api/incidents.json
更新
手動。インシデント発生から 24 時間以内に追記
スキーマ
ファイル内 _comment に記載
リクエスト例 
curl -s https://metal.freedom-yield.com/api/incidents.json | jq

Network

本ノードのピアセット内の peer validator の公開・匿名化されたビュー。

peer-geo.json

GET · JSON

本ノードのピアセットにいる peer validator の地理分布(NodeID / lat-lng / 国 / 都市 / 国コード)。NodeID は on-chain で公開済、IP は含みません。

URL
/api/peer-geo.json
更新
1 時間ごと(上流の geo API への配慮として TTL キャッシュ)
使用箇所
TOP ページ #network セクションの world map
リクエスト例 
curl -s https://metal.freedom-yield.com/api/peer-geo.json | jq '.totalPeers'

Network observability (時系列)

Metal Blockchain validator set の集中度・手数料分布・出入りを、append-only で日次サンプリング。 本ノードの local metalgo から platform.getCurrentValidators を叩いて生成しているので、 出典はチェーン本体が使うものと同じ authoritative RPC です。シリーズは 2026-05 起点、以後無期限に蓄積。 preview ファイルは描画用に最新 24〜30 件、history ファイルは全件を保持します。

peers-gini.json

GET · JSON · preview

validator-set 集中度の直近 24 日次サンプル。各エントリ: ts、gini (stake の Gini 係数、0 = 完全平等、1 = 単一独占)、top10_share (上位 10 validator の stake 占有率)、metallicus_share (Metallicus 系として識別された validator の占有率)、validator_count (その日の active validator 数)。

URL
/api/peers-gini.json
更新
毎日 13:00 JST (04:00 UTC)
Retention
直近 24 件(in-page 描画用)。フル履歴は下記。
リクエスト例 
curl -s https://metal.freedom-yield.com/api/peers-gini.json | jq '.entries[-1]'

peers-gini-history.jsonl

GET · JSONL · 全件

Gini / top-10 share / Metallicus share / validator count の全件 append-only ミラー。1 行 1 JSON オブジェクト。preview の 24 件を超える長期分析や独自描画に。schema は peers-gini.json エントリと同じ。

URL
/api/peers-gini-history.jsonl
更新
毎日 13:00 JST (04:00 UTC) に追記のみ
Retention
無期限。成長は ~150 bytes/日 ≈ 55 KB/年。
リクエスト例 
curl -s https://metal.freedom-yield.com/api/peers-gini-history.jsonl | tail -7 | jq -s '[.[] | .validator_count] | {min: min, max: max, last: .[-1]}'

fee-market.json

GET · JSON · preview

active validator set の delegation fee 分布の直近 30 日次サンプル。各エントリ: ts、n (validator 数)、mean、パーセンタイル p10/p25/p50/p75/p90、max、self_fee_pct (本ノードの fee)、self_percentile (本ノードの分布上の位置、0〜1)。「自 fee が market のどこに位置するか」を全 validator を個別スクレイプせずに即答できます。

URL
/api/fee-market.json
更新
毎日 13:00 JST (04:00 UTC)
Retention
直近 30 件。フル履歴は下記。
リクエスト例 
curl -s https://metal.freedom-yield.com/api/fee-market.json | jq '.entries[-1] | {p10, p50, p90, self_fee_pct, self_percentile}'

fee-market-history.jsonl

GET · JSONL · 全件

fee-market history の全件 append-only ミラー。schema は fee-market.json エントリと同じ。fee の compression / dispersion を長期窓で分析するのに使います。特に ACP-176 (Fortuna, 2026-05) 以降 validator が gas-target を config できるようになったので、validator collective behavior と fee 動向の関係分析が初めて意味を持ちます。

URL
/api/fee-market-history.jsonl
更新
毎日 13:00 JST (04:00 UTC) に追記のみ
Retention
無期限。成長は ~180 bytes/日 ≈ 65 KB/年。

peers-changes.json

GET · JSON

active validator set の最新 diff: 前回 snapshot 以降に参加した NodeID、離脱した NodeID、(本ノードの directory に既知の場合のみ)参加 validator の運用者名 + 自己 stake。validator turnover を 2 つの full snapshot を自分で diff せずに watch できます。

URL
/api/peers-changes.json
更新
毎日 13:00 JST (04:00 UTC)。append ではなく置換。
Schema
{ generated_at, had_previous_snapshot, new_count, departed_count, new: [{node_id, name?, self_stake_metal}], departed: [{node_id}] }
リクエスト例 
curl -s https://metal.freedom-yield.com/api/peers-changes.json | jq '{new_count, departed_count}'

peers-history-index.json

GET · JSON · index

日次の validator 全 set snapshot の index(各日 gzip で ~28 KB)。エントリ: date / filename / size_bytes。snapshot 本体は /api/peers-history/<filename> に置かれ、その日の全 active validator(NodeID / stake / fee / uptime / delegators 一覧)を含みます。特定日の per-validator 状態が必要な時(集計値ではなく)に使います。

URL
/api/peers-history-index.json
snapshot URL
/api/peers-history/peers-YYYY-MM-DD.json.gz
更新
毎日 13:00 JST (04:00 UTC)
Retention
無期限。成長は ~28 KB/日 ≈ 10 MB/年。
例: 昨日の全 set snapshot を取得 
YDAY=$(date -u -v-1d +%Y-%m-%d)  # Linux: date -u -d 'yesterday' +%F
curl -s "https://metal.freedom-yield.com/api/peers-history/peers-${YDAY}.json.gz" | gunzip | jq '.validators | length'

Schedule

今後の renewal イベントを iCalendar feed で subscribe できます。

schedule.ics

GET · iCalendar

今後の validator-renewal イベントを公開 iCalendar feed 形式で配信。Google Calendar / Apple Calendar / 任意の iCal クライアントに subscribe すれば、次の cycle renewal 時にアラートを受け取れます。

URL
/calendar/schedule.ics
更新
毎日 09:00 JST
Subscribe
カレンダーアプリの「URL から追加」フォームに上記 URL を貼り付け。ワンクリック Google subscribe ボタンは TOP ページ 運用カレンダー セクションにあります
中身確認 
curl -s https://metal.freedom-yield.com/calendar/schedule.ics | head -40

上流 canonical sources

本サイト上の全データはこちらに由来します。万一 conflict した場合はこちらが正です。

Metal Blockchain P-Chain RPC

POST · JSON-RPC

validator set / stake / uptime / delegation の authoritative source。本サイトの validator.json は 5 分ごとにここから取得しています。

URL
https://api.metalblockchain.org/ext/bc/P
運営
Metallicus / Metal Foundation
使用メソッド
platform.getCurrentValidators を NodeID でフィルタ
リクエスト例 
curl -s -X POST -H "content-type:application/json" \
  --data '{"jsonrpc":"2.0","id":1,"method":"platform.getCurrentValidators","params":{"subnetID":"11111111111111111111111111111111LpoYY"}}' \
  https://api.metalblockchain.org/ext/bc/P \
  | jq '.result.validators[] | select(.nodeID=="NodeID-yyPvtQHTA4FZU5cJtjWZa7RVBpWU3i5v")'
