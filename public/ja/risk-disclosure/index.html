合理的評価者が指摘するであろう事項

リスク開示

本 validator への委任、または本 validator への依拠に伴う既知の制約とリスクを記載する。意図は率直な開示であって威圧ではない。 各項目は、合理的な評価者が due diligence で取り上げるであろう事実 — それを我々の側から先に提示する。

既知のリスク

1. Self-stake が小規模

Self-stake は小規模である。委任受入容量は protocol 設計により self-stake の 5 倍に上限が設定されている。受入容量は 再登録時に運用者が self-stake を追加した分だけ拡大する。現在値は status セクションおよび 運用日誌 に公開しており、cycle 期間中は変動しない。

2. validator インフラが単一リージョン

validator は単一リージョンの単一 VPS で稼働している。multi-region failover は存在しない。当該 provider のリージョン 障害は validator downtime に直結する。事業継続性ページは本シナリオの復旧 model を文書化しているが、それは「回避」ではなく 「復旧」である。

3. 委任の集中

少数の大口委任者が受入 stake を集中させる可能性がある。cycle 末に大口委任者 1 件が抜けるだけで本 validator の経済構造は 大きく変動する。これは小規模 validator である事実の帰結であり、現スケールにおいて運用者が取り得る mitigation は存在しない。

4. subnet 採用は保証されない

本 validator は Metal Blockchain primary network に参加している。将来の subnet validator set への組み入れは、 当該 subnet operator の裁量による。本サイト上の表現が事前選定・割当・ subnet operator との bilateral arrangement を 意味するものは一切ない。

5. public web の可用性 ≠ validator uptime

metal.freedom-yield.com が到達不能でも metalgo は consensus signal を発信し続ける場合がある。 逆にサイトが見えていても validator が degrade している場合がある。validator の状態確認は必ず explorer または /api/validator.json で on-chain に確認すること。

6. subnet 固有要件は別インフラを要する可能性

subnet validation は通常、metalgo プロセスを追加で要し、専用 capacity も必要となる。本 validator の 現行インフラは subnet validation を自動的にカバーしない。subnet 参加は別個の取り組みであり、実施する場合は commitment §8 に従い事前に公示する。

7. 規制 / コンプライアンス対応は別途レビューが必要

本 validator は primary network 参加者である。コンプライアンス attestation を要する規制対象 counterparty(銀行、 規制対象ファンド、同等の規制対象 entity 等)は、独立の bilateral due diligence を実施する必要がある。本ページは compliance attestation ではなく、本サイトの記述は attestation として解されるものではない。

8. 単一運用者依存

本 validator は単一の個人によって運用されている。職務分掌は無く、 on-call rotation チーム / 独立 change-approval board / 組織的な意思決定冗長性は存在しない。 Constitution および Operating Model で「AI が提案、 operator が承認、 operator が実行、 AI が検証」という pattern を定義しているが、 最終承認と最終実行の権限は同一人物である。 日本の 営業時間外の応答時間は best-effort であり、 guaranteed ではない。 renewal 時に operator が応答不可になった場合、 validator は current cycle 終了時に自然に validator set から離脱し、 委任された stake は no-slashing 仕様により 自動的に返却される (continuity ページ参照)。 つまり validator 自体は operator 不在による元本損失リスクを孕まないが、 operator の継続的応答に依存する評価者は本制約を考慮されたい。
