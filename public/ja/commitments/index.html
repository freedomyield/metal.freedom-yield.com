運用者の commitment

9 つの明示的な commitment — いずれも破った場合、外部から観測可能な形で書かれている。願望としての marketing 文ではなく、 本サイト・on-chain の記録・公開リポジトリを読めば第三者が監査できる behaviour として記述する。

10 個の commitment

再登録の透明性

毎月の cycle 毎に発行される AddPermissionlessValidatorTx の ID は、explorer link 付きで 運用日誌 に公開する。各 entry には期間 start / end、self-stake 額、手数料、canonical な explorer URL を含む。これにより、本サイト上の表示値を信用せずとも、第三者が公開情報のみから再登録の全履歴を再構成できる。

インシデントの公開開示

全ての SEV-1 / SEV-2 incident は、解決から 24 時間以内に incident ページ に timeline / root cause / impact を記載する。実体は /api/incidents.json の JSON。empty list は「隠した list」ではなく、文字通り該当 event がないことを意味する。

Non-custodial 運用

委任 stake は常に委任者の wallet に残る。運用者が委任 METAL を引き出す・移動する・凍結することはいかなる場面でも不可能。 Avalanche 派生の P-Chain protocol は、運用者の action 有無に関わらず cycle 終了時に委任 stake を所有者へ返却する。

インフラについて誇張しない

Metallicus 推奨 minimum spec を満たす production-grade VPS で稼働する。実体を超える「institutional-ready」 「multi-region」「enterprise SLA」「subnet operator」等の主張はしない。現在の capacity は 事業継続性 と リスク開示 に文書化する。

validator 健全性を最優先

観測機能 / UX 改善 / 新機能と metalgo の健全性が resource 上で競合する場合、validator プロセスを優先する。 docs/CONSTITUTION.md §2 に明文化。実運用上は、metalgo を制約する前に補助的な dashboard を degrade / 一時停止する。

Web と validator の分離

validator ホストと public web ホストは独立。web 障害は metalgo uptime に影響せず、validator 障害は public site を壊さない。両側はそれぞれ独立に観測・復旧でき、片方を触らずにもう片方を扱える — シナリオ別の動作は 事業継続性 参照。

個人向け marketing をしない

SEO push / growth content / 有料獲得は行わない。読者層は due diligence を行う institutional reader であり、利回りを 追う個人委任者ではない。本ページが noindex なのは、検索エンジンが配信チャネルではないという方針と整合する。

廃止時の合理的事前予告

本運用者が validator 運営を停止する場合、委任者が再配分できるよう少なくとも 90 日前に公開予告を commit する。 予告は本サイトおよび public repository への commit として現れ、いずれも timestamp 付きで外部から観測可能である。

セキュリティ機微情報を公開しない

ホストの path、IP、SSH credential、BasicAuth hash、ntfy topic 等は docs/CONSTITUTION.md §4.1 で SECRET 分類とし、public リポジトリ / サイトコンテンツ / issue / commit message に一切出さない。public surface に 現れるのは validator の state であって、それを生む infrastructure ではない。

営業日 24 時間以内の問い合わせ初回応答

info@metal.freedom-yield.com 宛の問い合わせには、 日本の営業日(週末・日本の祝日を除く) ベースで 24 時間以内に初回応答する。 初回応答は質問への実質的な回答か、 明確な bilateral 次ステップの提示のいずれかであり、 受領通知 1 行で済ませることを target としない。 問い合わせの送信経路と推奨記載項目は 問い合わせページ に記載 — 氏名や所属の明示は **不要** で送信できる。

参照

これらの commitment の根拠となる憲章相当の文書は public repository の docs/CONSTITUTION.md にある。本ページと対になる文書 — 運用者が 主張しない こと、合理的評価者が知るべき limit — は リスク開示 である。
