オープン標準

Transparent Validator Pledge

ブロックチェーン validator 運用者向けの最小開示標準。CC0(パブリックドメイン)で公開。 uptime / インシデント / 手数料安定性 / 撤退告知 / 身元開示の 5 条文で構成。 どのチェーンのどの validator でも採用 / 改変 / fork 可能です。Freedom Yield は specimen(実装例)と提案者として publish しているのであって、authority として publish しているわけではありません。

  1. ホーム
  2. Transparent Validator Pledge

これは何か

validator が delegator / 評価者 から都度の質疑なしに評価される状態を作るために、最低限 publish しておくと役に立つ artifacts を記述した 短いパブリックドメイン文書です。baseline であって ceiling ではありません。

動機

どの validator のどの reviewer も、結局同じいくつかの質問にたどり着きます — uptime 履歴、インシデント対応、手数料の安定性、撤退通知、契約の相手は誰か。 最小開示パターンを共有することで、reviewer 側の摩擦が減り、選定時の不意打ちも減ります。匿名運用は引き続き valid な選択肢で、本 Pledge は public な姿勢を選んだ validator のためのものです。

5 つの条文

  • 第 1 条 — uptime 実績記録。cycle 別の機械可読 uptime 記録、on-chain で第三者がクロスチェックできる形。
  • 第 2 条 — インシデント透明性。日時 / 重大度 / 影響範囲 / 根本原因 / 解決時間付きの運用インシデントログ。
  • 第 3 条 — 手数料の安定性。現在の手数料を publish、変更は定められた告知期間を置いて事前告知。
  • 第 4 条 — 撤退告知。運用停止の判断について、事前にコミットされた最小リードタイム。
  • 第 5 条 — 身元開示標準。ブランド名 / 安定した連絡先 / 国レベルの管轄 — それ以上は要求しない。

Freedom Yield は実装例として

Freedom Yield は本 Pledge を採用し、以下の mapping を publish します。他の adopter は別の mapping でも構いません — 必須 URL 構造は存在しません。

  • 第 1 条 — uptime 実績記録: /ja/journal/ + /api/uptime-cycles.json
  • 第 2 条 — インシデント透明性: /ja/incidents/ + /api/incidents.json
  • 第 3 条 — 手数料の安定性: /ja/commitments/(手数料方針セクション)+ /api/validator.json
  • 第 4 条 — 撤退告知: /ja/commitments/(撤退告知セクション)— 90 日
  • 第 5 条 — 身元開示: /ja/jurisdiction/ + ブランド名「Freedom Yield」+ info@metal.freedom-yield.com

ライセンス

本 Pledge は CC0 1.0 Universal のもとパブリックドメインに置かれます。帰属表示不要。 fork / 派生物 / 翻訳すべて自由です。中央レジストリは存在せず、採用は adopter 側の URL 上で signal します。

採用方法

  • 自サイトの安定 URL に、どのバージョンの Pledge に準拠しているかを宣言した compliance statement を publish する。
  • 任意で、機械可読な adoption manifest(推奨ファイル名 /api/pledge-adoption.json)を、本文中のスキーマ例に従って publish する。
  • リポジトリの README から compliance URL にリンクし、reviewer が辿れるようにする。

貢献

改善・翻訳・fork のいずれも pull request で歓迎します。維持者の権限は編集上のものに限り、編集で解決できない不一致は fork で解決可能です。
