アイデンティティ署名(Phase α Merkle DAG anchor)

live(manifest)· live(anchor)

署名付きアイデンティティマニフェストは、 validator の staker.key および BLS signer.key とは独立した運用者専用 identity key(ed25519)で生成されます。 検証には namespace freedom-yield/validator-identity の OpenSSH signature を使います。 validator の signing key はこの過程で一切使用しません。

identity モデルは 3 枝の Merkle DAG です: identity_branch(= 運用者 identity key の履歴)、 observations_branch(= cycle 毎の uptime / 手数料 / self-stake / delegator events)、 artifacts_branch(= 公開 artifact manifest)。 3 つの branch root は dag_root_computed として 1 つに結合され、 限定権限 metalfreedom@anchor によって Metal A-chain(= PulseVM / XPRNetwork)に 4 つの eosio.token::transfer memo — 各 branch(fya1c<N>-id: / -ob: / -ar:)と統合 root(fya1c<N>:<dag_root_computed>)— として刻まれます。 旧 P-Chain memo 方式(2026-06-20 撤回)は現行 Metal mainnet Durango の protocol rule と非互換でした。

verifier 手順は 7 step recipe です(artifact 取得 → signature → fingerprint → 3 branch root → DAG-root 再計算 → source/receipt 一致 → on-chain 4-memo cross-check)。 独立した参照実装が 2 種あります: portable shell 関数(gen-identity.sh 内)と Python 参照(tests/identity-verification-vectors/ 下)、 自動 test script で bit-for-bit 一致を pinning。 合成テストベクトル 5 件を公開しているので、 監査者は第三言語で verifier を独自実装して照合できます。

snapshot + rotation cadence の方針。 identity.json は発行時点の運用者状態の署名済 snapshot であり、 heartbeat ではありません。 cycle transition 時の anchor receipt は同じ commitment を reaffirm し、 運用者が更新版 manifest を公開するまで同じ dag_root_computed を刻み続けます。 更新トリガは: (1) ed25519 運用者 identity key の年次 rotation(次回 2027-06-22)、 (2) bound set への新 artifact 追加、 (3) 重要 policy 変更、 の 3 点です。 複数 cycle にわたって dag_root_computed が変化しないのは設計通りで、 「該当期間に運用者は新たな commitment を主張していない」ことを意味します。 業界類似事例: Certificate Transparency log(= append-only、 root は新エントリで拡張)、 DNSSEC zone signing(= 定期 re-sign + 公開 cadence)、 long-lived OpenSSH 鍵 + rotation policy。 Metal エコシステム内で validator identity binding の標準 pattern は未定であり、 本面は novel です。
