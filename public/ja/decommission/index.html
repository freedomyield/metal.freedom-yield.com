運用者が停止する場合

廃止予告ポリシー

本 validator が運営停止に至る場合、 委任者が再配分できる時間を確保するため十分に事前に公開予告する方針。 予告は本サイトと public repository の commit に同時に現れ、 両者とも外部から観測可能で timestamp 付き。 本ページはこのポリシー自体、 適用範囲、 そして「廃止に含めないもの」 を記述する。

現在の状態: 廃止の予定なし。 以下のポリシーは dormant。

  1. ホーム
  2. 廃止予告ポリシー

最低 lead time

本運用者が validator 運営を停止すると決定した場合、 validator が参加する最終 cycle の 少なくとも 90 日前 までに公開廃止予告を commit する。 90 日 floor は運用者の unilateral commitment であり、 規制 / 契約義務ではない。 ただしこの commitment は観測可能である: 予告は timestamp 付きの 2 surface に同時に現れ(下記参照)、 90 日 floor からの逸脱は予告 timestamp と最終 cycle の endTime を比較すれば外部から visible になる。

本 commitment は 運用者 commitment ページ の #8 として記録し、 Transparent Validator Pledge Article 4 に mapping する。

予告の現れ方

廃止予告は同じ window 内で独立な 2 surface に公開される:

本サイト
本ページと top page に目立つ banner、 さらに 運用日誌 に dated entry を追加する。 site は人間可読 surface。
public repository
本ページ等の公開 artifact 内容を修正する commit。 commit message は chore(decommission): notice — final cycle <N>, target end <ISO date> 形式で tag。 commit は機械可読 surface、 author timestamp は外部検証可能。

両 surface には以下が記載される: validator が完走する最終 cycle 番号、 同 cycle の target endTime、 運用者として開示可能な範囲の rationale、 現委任者に推奨される action。 予告は委任者に本サイト上での action を求めない — 再配分の各 step は委任者の wallet 内で on-chain に実行される。

なぜ 90 日か

90 日 floor は、 typical な委任者の attention cycle に対し十分な幅となるよう選択した:

  • Avalanche 派生 P-Chain protocol は、 運用者 action の有無に関わらず cycle 終了時に委任 stake を所有者へ返却する。 廃止 window 中に slashing risk はない。
  • validator surface を月次で確認する委任者は、 validator 停止前に少なくとも 3 cycle 分予告を目にできる。
  • 別 validator への再委任には現委任期間の終了待ち(typically 数週間)が必要。 90 日でこの window に十分余裕がある。
  • 委任者が institutional の場合、 90 日 window は大半の社内 change management cadence(board 通知、 signoff、 treasury 再配分、 監査証跡)と整合する。

Transparent Validator Pledge は「validator が大規模 / institutional 委任を host する場合はより長く」 と suggest する。 institutional 規模を host する運用者は notice をその分延長することになる。 90 日 commitment は floor であって ceiling ではない。

廃止に該当するもの / しないもの

廃止に隣接する事象がいくつかあるが、 これらは 廃止ではない ため 90 日予告の trigger とならない:

Cycle end
毎月の cycle 終了は normal operation。 運用者が同じ NodeID で新 cycle を再登録、 委任者は連続サービスを受ける。 履歴は 運用日誌。
インシデント由来のダウンタイム
SEV-1 / SEV-2 incident は incidents 下で扱う downtime event。 同じ NodeID で復旧、 廃止ではない。
計画的 key rotation
新 NodeID を伴う scheduled rotation は事前文書化された continuity event。 廃止扱いではない。 手順は docs/KEY_ROTATION.md。
Host 移行
同じ NodeID を維持しつつ validator host を入れ替えるのは 事業継続性 ページに記載の continuity event。 廃止ではない。
Fee / self-stake 変更
fee policy 変更は commitment 階の event で、 別の notice protocol を持つ(commitment #1, fee stability)。 運用者が同時に廃止も決定しない限り、 本ページの 90 日予告は trigger しない。

廃止予告を trigger する唯一の条件は: 運用者が本 NodeID 上で本 validator の運営を停止する決定をし、 後継 cycle の計画がない場合。

本 commitment が documentation のどこに存在するか

  • 運用者 commitment — commitment #8(unilateral commitment 本体)。
  • Transparent Validator Pledge — Article 4(本 commitment が mapping する open standard)。
  • docs/TRANSPARENT_VALIDATOR_PLEDGE.md — Pledge 全文 + Freedom Yield specimen mapping。
  • 事業継続性 — 廃止と明示的に区別される隣接 event(host 移行、 incident response 等)。

本ページが「ではない」もの

本ページは契約上の SLA ではない。 特定管轄の法令下の規制開示でもない。 外部から観測可能であるが、 enforce するのは運用者自身の discipline であって外部 authority ではない、 unilateral commitment。 unilateral commitment より強い保証を必要とする評価者は、 本ページを複数の input の 1 つとして扱うべきで、 唯一の input としては扱うべきでない。

本ページは exit signal でもない。 執筆時点で 廃止の予定はない。 ポリシーを事前に文書化するのは、 仮に発動する場合に発動 mechanism が既知 / 検証可能であるようにするため。
