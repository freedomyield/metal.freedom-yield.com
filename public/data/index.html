Open data

Every claim on this site comes from one of the endpoints below. Each one is publicly readable — verify anything yourself with curl, an iCalendar app, or your tool of choice. Nothing here requires authentication.

Validator state

Live identity, stake, uptime, and bootstrap status of the node itself.

validator.json

GET · JSON

Live validator identity, stake, uptime%, and P/X/C-Chain bootstrap status. The single source of truth that the home page status card reads from.

URL
/api/validator.json
Updated
Every 5 minutes — written by scripts/node-info.sh from local metalgo and the canonical P-Chain RPC
Schema
Self-documenting: top-level _comment describes how each field is derived
Example request 
curl -s https://metal.freedom-yield.com/api/validator.json | jq

evidence.json

GET · JSON

Machine-readable evidence manifest — combines live validator state with static project commitments and the list of public pages. Designed to be consumed by institutional reviewers performing automated due diligence.

URL
/api/evidence.json
Updated
Daily — written by scripts/gen-evidence.sh from validator.json + static project config
Schema
Self-documenting: top-level _comment describes the manifest layout
Example request 
curl -s https://metal.freedom-yield.com/api/evidence.json | jq

Uptime & track record

The audit trail. Daily samples for ~90 days, plus closed-cycle history that accumulates indefinitely.

uptime-recent.json

GET · JSON

Rolling 90-day window of daily uptime samples. Each entry: observed-at timestamp, uptime%, peer count, bootstrap status, validator period bounds.

URL
/api/uptime-recent.json
Updated
Daily at 09:10 JST
Retention
Rolling 90 days; older entries roll into the cycles file below
Example request 
curl -s https://metal.freedom-yield.com/api/uptime-recent.json | jq '.entries[0]'

uptime-cycles.json

GET · JSON

Each closed validation period appears as one row: on-chain start/end timestamps, final uptime%, tx ID, and an explorer URL for independent audit. The long-horizon record that grows ~12 entries per year while the monthly-cycle plan runs.

URL
/api/uptime-cycles.json
Updated
On cycle close (~once per month during the current phase)
Audit
Each row links to explorer.metalblockchain.org for tx verification
Example request 
curl -s https://metal.freedom-yield.com/api/uptime-cycles.json | jq '.cycles | length'

incidents.json

GET · JSON

Operator-maintained incident log. Each entry: id, ISO 8601 date, severity (info / minor / major / critical), title, summary, impact, and resolution. An empty array is not a hidden list — it means no operational anomalies have occurred.

URL
/api/incidents.json
Updated
Manually, within 24 hours of any incident
Schema
Documented inline in the file's _comment field
Example request 
curl -s https://metal.freedom-yield.com/api/incidents.json | jq

Network

Public, anonymised view of the wider validator network as seen from this node.

peer-geo.json

GET · JSON

Geographic distribution of peer validators currently in this node's peer set. Each entry: NodeID, lat/lng, country, city, country code. NodeIDs are already on-chain public; no IPs are exposed.

URL
/api/peer-geo.json
Updated
Hourly (TTL cache to be polite to upstream geo APIs)
Used by
The world map on the home page #network section
Example request 
curl -s https://metal.freedom-yield.com/api/peer-geo.json | jq '.totalPeers'

Network observability (time-series)

Append-only daily samples of the Metal Blockchain validator set — concentration, fee distribution, and turnover. Derived from platform.getCurrentValidators on this node's local metalgo, so the source is the same authoritative RPC the chain itself uses. These series start in May 2026 and grow indefinitely; preview files trim to the last 24–30 entries for chart rendering, history files keep every sample.

peers-gini.json

GET · JSON · preview

Last 24 daily samples of validator-set concentration. Each entry: ts, gini (stake Gini coefficient, 0 = perfectly even, 1 = single-validator monopoly), top10_share (fraction of total stake held by top 10 validators), metallicus_share (fraction held by validators identifiable as Metallicus-operated), validator_count (number of active validators that day).

URL
/api/peers-gini.json
Updated
Daily at 13:00 JST (04:00 UTC)
Retention
Last 24 entries for in-page rendering. Full history below.
Example request 
curl -s https://metal.freedom-yield.com/api/peers-gini.json | jq '.entries[-1]'

peers-gini-history.jsonl

GET · JSONL · full

Append-only line-delimited JSON mirror of the full Gini / top-10 / Metallicus share / validator count history. One JSON object per line. Use this for long-window analyses or charting beyond the 24-entry preview. Same schema as peers-gini.json entries.

URL
/api/peers-gini-history.jsonl
Updated
Daily at 13:00 JST (04:00 UTC), appended only
Retention
Keep-forever. Growth: ~150 bytes/day ≈ 55 KB/year.
Example request 
curl -s https://metal.freedom-yield.com/api/peers-gini-history.jsonl | tail -7 | jq -s '[.[] | .validator_count] | {min: min, max: max, last: .[-1]}'

fee-market.json

GET · JSON · preview

Last 30 daily samples of the validator delegation-fee distribution across the active set. Each entry: ts, n (validator count), mean, percentiles p10/p25/p50/p75/p90, max, self_fee_pct (this node's fee), self_percentile (where this node sits in the distribution, 0–1). Use to answer "where does my fee sit in the market?" without scraping every validator individually.

URL
/api/fee-market.json
Updated
Daily at 13:00 JST (04:00 UTC)
Retention
Last 30 entries. Full history below.
Example request 
curl -s https://metal.freedom-yield.com/api/fee-market.json | jq '.entries[-1] | {p10, p50, p90, self_fee_pct, self_percentile}'

fee-market-history.jsonl

GET · JSONL · full

Append-only mirror of the full fee-market history. Same schema as fee-market.json entries. Use for fee compression / dispersion analysis over long windows — especially relevant after ACP-176 (Fortuna, 2026-05) introduced validator-configurable gas-target preferences.

URL
/api/fee-market-history.jsonl
Updated
Daily at 13:00 JST (04:00 UTC), appended only
Retention
Keep-forever. Growth: ~180 bytes/day ≈ 65 KB/year.

peers-changes.json

GET · JSON

Most recent diff of the active-validator set: NodeIDs that joined since the previous snapshot, NodeIDs that departed, and (where known to this node's directory) the operator name + self-stake for joiners. Use to watch validator turnover without diffing two full snapshots yourself.

URL
/api/peers-changes.json
Updated
Daily at 13:00 JST (04:00 UTC). Replaces (not appends).
Schema
{ generated_at, had_previous_snapshot, new_count, departed_count, new: [{node_id, name?, self_stake_metal}], departed: [{node_id}] }
Example request 
curl -s https://metal.freedom-yield.com/api/peers-changes.json | jq '{new_count, departed_count}'

peers-history-index.json

GET · JSON · index

Index of daily full-set validator snapshots, each gzipped (~28 KB / day). Entries list date, filename, size_bytes. Snapshots themselves live at /api/peers-history/<filename> and contain every active validator on that day (NodeID, stake, fee, uptime, delegators list). Use this when you need the actual per-validator state on a specific historical date, not just aggregates.

URL
/api/peers-history-index.json
Snapshot URL
/api/peers-history/peers-YYYY-MM-DD.json.gz
Updated
Daily at 13:00 JST (04:00 UTC)
Retention
Keep-forever. Growth: ~28 KB/day ≈ 10 MB/year.
Example: fetch yesterday's full snapshot 
YDAY=$(date -u -v-1d +%Y-%m-%d)  # Linux: date -u -d 'yesterday' +%F
curl -s "https://metal.freedom-yield.com/api/peers-history/peers-${YDAY}.json.gz" | gunzip | jq '.validators | length'

POST · JSON-RPC

The authoritative source for validator set, stake, uptime, and delegation data. Our validator.json reads from here every 5 minutes.

URL
https://api.metalblockchain.org/ext/bc/P
Maintained by

Self-identity metadata

This validator's own publishable identity information.

validator-directory.json

GET · JSON

A small JSON file containing this validator's own NodeID → { name, url, type } entry. The chain itself doesn't expose websites or display names, so this file lets the public site link the NodeID to a human-readable identity.

URL
/api/validator-directory.json
Updated
Rarely — only when this validator's own metadata changes

Use freely, cache politely

All endpoints are unauthenticated and CORS-permitted for public read. There is no rate limit enforced today, but please be polite — set a sensible TTL on your client (15+ minutes is fine for most use cases) so a busy day doesn't accidentally hammer the origin. If you build something on top of this data, drop us a note at bp@freedom-yield.com — we love seeing what people do with it.

No SLA. No uptime guarantee for the endpoints themselves — only for the validator they describe. If an endpoint serves stale data after an extended outage, the canonical sources above are the ground truth.
