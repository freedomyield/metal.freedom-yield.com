Cycle-by-cycle audit packet

live

A JSONL feed at /api/cycle-history.jsonl is live. Each line is one closed cycle, joining /api/uptime-cycles.json with /api/incidents.json so a reader can stream the full audit packet line-by-line — the feed itself is authoritative for how many cycles have closed so far (curl -s .../cycle-history.jsonl | wc -l), not this page. The schema is published at /api/cycle-history.example.jsonl; the generator script lives at scripts/gen-cycle-history.sh and the format / consumption guide is at docs/CYCLE_HISTORY.md. New leaf lines are appended at each cycle close by an operator-host cron (metal-cycle-history, 5-min tick); the cycle observations are then summarised into the observations_branch of /api/anchor-source.json by gen-anchor-source.sh at anchor time.

Identity binding (Phase α Merkle DAG anchor)

live (manifest) · live (anchor)

A signed identity manifest is produced by a dedicated operator identity key (ed25519), independent of the validator's staker.key and BLS signer.key. Verification uses OpenSSH signatures with namespace freedom-yield/validator-identity. The validator's signing keys are not used for this process.

The identity model is a three-branch Merkle DAG: identity_branch (= operator identity-key history), observations_branch (= per-cycle uptime / fee / self-stake / delegator events), and artifacts_branch (= the published-artifact manifest). The three branch roots combine into a single dag_root_computed that is inscribed on Metal A-chain (= PulseVM / XPRNetwork) by a narrow metalfreedom@anchor permission, across four eosio.token::transfer memos — one per branch (fya1c<N>-id: / -ob: / -ar:) plus the combined root (fya1c<N>:<dag_root_computed>). The prior P-Chain memo design (retired 2026-06-20) was incompatible with current Metal mainnet Durango protocol rules.

The verifier procedure is a seven-step recipe (fetch artifacts → signature → fingerprint cross-check → three branch roots → DAG-root recompute → source/receipt equality → on-chain four-memo cross-check). Independent reference implementations: a portable shell function inside gen-identity.sh and a Python reference under tests/identity-verification-vectors/, with bit-for-bit equivalence pinned by an automated test script. Five synthetic test vectors are published so an auditor can implement and validate a third-language verifier.

Snapshot + rotation cadence. identity.json is a signed snapshot of operator state at the moment of issue, not a heartbeat. Anchor receipts at cycle transitions reaffirm the same commitment until the operator publishes an updated manifest. The intended update triggers are: (1) annual rotation of the ed25519 operator identity key (next: 2027-06-22), (2) addition of a new artifact to the bound set, (3) material policy change. A dag_root_computed that does not change across multiple cycles is by design — it means the operator has not asserted any new commitment in that window. Industry analogues: Certificate Transparency log (= append-only, root extends with new entries), DNSSEC zone signing (= periodic re-sign with documented cadence), long-lived OpenSSH keys with rotation policy. There is no Metal-ecosystem-standard pattern for validator identity binding; this surface is novel.

Service scope

This sub-section answers what the operation does, what it does not do, and where the responsibility boundary sits. It is an index into the canonical sources; the substance lives in the linked pages and runbooks.

What is offered
Operation of a Metal Blockchain mainnet validator under the responsibility model described in the constitution and operating model.
What is not offered
Custody of delegator funds, off-chain custody services, pre-committed subnet operation, smart-contract execution beyond what the protocol requires of a validator, and any service outside the linked surface.
Responsibility boundary
Validator availability, public verification surface, and identity-manifest signing — per the linked sources below.
