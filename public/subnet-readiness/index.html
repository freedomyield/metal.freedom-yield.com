Compute headroom for additional metalgo

not pre-provisioned

Subnet validation typically requires an additional metalgo process and dedicated CPU/RAM/disk. The current single-VPS deployment does not reserve spare capacity for a subnet. Provisioning a separate subnet-validation host is feasible with reasonable notice, but it is not pre-built. This is a deliberate honesty: small validator, no idle inventory.

Current posture
Single VPS sized for primary network only
On invitation

KYC / compliance posture

bilateral on request

This validator does not perform KYC at the validator layer; delegation is permissionless on the primary network. Counterparties (banks, regulated funds, similar regulated entities) requiring KYC or compliance attestation must perform bilateral due diligence with the operator. This page is not a compliance attestation.

Key custody

self-custodied

Self-custodied ed25519 staking key on a single dedicated validator host. Encrypted backups maintained off-host per a documented backup policy. No third-party custody. No shared key material. The operator identity key (used for off-chain signed manifests) is a separate dedicated key, held off the validator host entirely.

Network-grade infrastructure

honest disclosure

Single-VPS deployment on a commercial host. Validator workload and public web are segregated to separate hosts, so a public-web outage does not affect validator uptime. Single-region; no multi-region failover. The recovery model is documented at /continuity/; it is recovery, not avoidance. The full topology, push direction, and key-separation principles are laid out at /reference-architecture/.

Subnet pilot readiness

bilateral on request

If invited to a subnet pilot, the operator can stand up a dedicated subnet-validation host on reasonable notice. The specific shape of any pilot — capacity sizing, response-time SLA, subnet-specific compliance, custody framework, communication cadence — is by necessity a bilateral conversation. This page does not pre-commit to any of those; it confirms willingness and structural feasibility.

What this page is not

This is not a compliance attestation, a regulatory disclosure, a bid for a specific subnet, or a representation that any particular evaluation framework has been satisfied. It is a one-page candid statement of what the current operation has, lacks, and could provision on request. The cross-linked artifacts (selection-evidence, risk-disclosure, commitments, jurisdiction, continuity) are the verifiable substance.
