# metal.freedom-yield.com

Public website and operational scripts for the **Freedom Yield** Metal Blockchain (Layer-0 by Metallicus, Avalanche fork) validator.

🇯🇵 日本語版: [README.ja.md](README.ja.md)

## What this is

This repository contains:

- **The public website** (`public/`) — landing page, validator status, delegate info, incident history, open data catalog. EN at `/`, JA at `/ja/`. Served by Caddy locally; deployed to the web host via GitHub Actions.
- **Operational scripts** (`scripts/`) — `node-info.sh` / `peer-validators.sh` / `notify.sh` / `dr-drill.sh` and friends. These run on the validator host to feed the public JSON endpoints, push anomaly alerts, exercise DR. See [TOOLKIT.md](TOOLKIT.md) for what's reusable for other Metal validators.
- **Runbooks** (`docs/`) — incident response, key rotation, disaster recovery, validator host setup, mainnet migration, validator renewal, security layers.
- **Manifest format guides** (`docs/`) — [`EVIDENCE_MANIFEST.md`](docs/EVIDENCE_MANIFEST.md) (live), [`CYCLE_HISTORY.md`](docs/CYCLE_HISTORY.md), [`IDENTITY_VERIFICATION.md`](docs/IDENTITY_VERIFICATION.md) (verifier side), [`OPERATOR_IDENTITY_SETUP.md`](docs/OPERATOR_IDENTITY_SETUP.md) (operator-side teaching reference), [`PHASE5_CHECKLIST.md`](docs/PHASE5_CHECKLIST.md) (operator-side execution checklist for the signed-manifest publish), [`PHASE6_CHECKLIST.md`](docs/PHASE6_CHECKLIST.md) (operator-side execution checklist for the per-cycle chain-anchor embed), and [`TRANSPARENT_VALIDATOR_PLEDGE.md`](docs/TRANSPARENT_VALIDATOR_PLEDGE.md). Schema, generation pipeline, and consumption commands for the public JSON / JSONL surfaces under `/api/`.
- **A local Tahoe testnet metalgo node** (`docker-compose.metalgo.yml`) for pipeline verification without spending real money.

The production validator (`metalgo` running on its own dedicated VPS with port 9651 public) is a separate concern. This repo only describes and documents it.

All work in this repository conforms to the supreme reference of [`docs/CONSTITUTION.md`](docs/CONSTITUTION.md) and the workflows defined in [`docs/OPERATING_MODEL.md`](docs/OPERATING_MODEL.md).

## Quick start

### Prerequisites

- Docker Desktop (or any Docker engine with Compose v2)
- macOS / Linux (Windows untested)
- Apple Silicon Mac: works natively (metalgo image has arm64 build)

### One-time setup

```sh
# Activate the secret-scanning pre-commit hook (local git config, not pushed)
git config core.hooksPath .githooks

# Optional: install gitleaks for stronger pre-commit checks
brew install gitleaks   # macOS

# Local env (mainly HTTP_PORT for port conflicts)
cp .env.example .env
```

### Run the site (Caddy)

```sh
make site-up        # starts Caddy → http://localhost:8080 (or HTTP_PORT)
make site-logs      # tail logs
make site-down      # stop
```

### Run a Tahoe testnet node (metalgo)

```sh
make node-up        # pull image + start, bootstraps in ~30s-2min
make node-status    # query NodeID + bootstrap, refresh public/api/validator.json
make node-logs      # tail metalgo logs
make node-down      # stop (data volume kept)
```

`make up` / `make down` start/stop both.

## Security posture

- **Pre-commit hook** (`.githooks/pre-commit`) blocks PEM private keys, AWS/GitHub tokens, `.env`, `.pem`/`.p12`/`staker.key` etc. before they hit a commit
- **CSP**: `default-src 'none'`-based, only specific resource types allowlisted
- **Local dev binds**: metalgo ports bound to `127.0.0.1` only — LAN-isolated. Production VPS uses a different compose with public bind
- **Containers**: `read_only` root FS, `cap_drop: [ALL]`, `no-new-privileges`
- **Secrets**: staking keys live in a Docker named volume, never on host filesystem; `.gitignore` covers PEM/p12/staker.*/signer.*/`.env`
- **Key rotation**: see [docs/KEY_ROTATION.md](docs/KEY_ROTATION.md)

## For other Metal validators

If you're running (or thinking about running) a Metal Blockchain validator, [TOOLKIT.md](TOOLKIT.md) inventories which scripts here are reusable for any Metal validator vs. which assume our specific topology. The short version: most of `scripts/` is generic chain-level operations (validator state, peer-set snapshots, uptime history, anomaly detection, ntfy push, DR drill, renewal calendar). The push / sync / bootstrap scripts are operator-specific reference material.

The public catalog at <https://metal.freedom-yield.com/data/> documents every JSON / JSONL feed the site exposes.
