# Anchor source (`/api/anchor-source.json`)

The canonical, machine-readable source that composes every A-chain anchor Freedom Yield broadcasts. The runtime file at `https://metal.freedom-yield.com/api/anchor-source.json` is generated by `scripts/gen-anchor-source.sh` from live observation sources; its `dag_root_computed` field is exactly the value inscribed on Metal A-chain via the HC-single 4-action pack described below. The published file is byte-identical to the **signed pre-image** the anchor was derived from — recomputing its three branch roots reproduces the four on-chain memos (`-id`, `-ob`, `-ar`, and the combined summary), so third-party evaluators can independently verify the on-chain anchor without trusting our tools.

## Status

Live. The broadcast pipeline (`scripts/sign-anchor-event.sh`) has anchored on Metal A-chain mainnet at the cycle 2 → cycle 3 transition (2026-07-04); the runtime `anchor-source.json` reflects that anchor's signed pre-image. Companion schema at `public/api/anchor-source.schema.v1.json`; placeholder-filled reference at `public/api/anchor-source.example.json`; design memo `project_merkle_dag_identity_anchor_design_20260701` (operator memory).

## Publish and distribution (= git-deploy)

The runtime `anchor-source.json` (and its detached `anchor-source.json.sig`) are **git-deploy owned**: the file `gen-anchor-source.sh` produces on the validator host is committed to the repo and distributed by the GitHub Actions deploy, which rsyncs the repo-tracked copy to both the validator-host internal Caddy and the public Xserver origin. It is **not** published by the validator-host runtime push (`scripts/push-to-web-host.sh`), and it is therefore **not** listed in `deploy/feed-excludes.txt`.

Because the published file is the exact committed pre-image that was signed and hashed for the on-chain anchor, the public URL, the repo copy, and the signed source are the same bytes — there is no separate push path that can drift or silently drop, which is the failure mode the earlier host-push route produced. Ownership is pinned in [`docs/DEPLOY_OWNERSHIP_MATRIX.md`](DEPLOY_OWNERSHIP_MATRIX.md); `anchor-receipt.json` and `anchor-history.jsonl` remain validator-pushed because they are produced only after the broadcast, off the deploy path.

## Design principles (= 4 mandatory)

1. **Verb discipline = observation / notarization only.** Every field name uses `_observed`, `_asserts`, `_computed`, `_at`, `_from`, `_by`, `_root`, `_seq`, `_hex`, `_count`, or `_pct`. Obligation verbs (`_target`, `_promised`, `_committed`, `_sla`, `_slo`, `_cadence`, `_guarantees`, `_ensures`, `_will_`, `_should_`, `_must_`, `_maintain`, `_pledged`) are grep-rejected by the generator before write. The anchor is a public notary, not a contract.
2. **P-chain redundancy is minimized.** Fields the Metal P-chain protocol already records natively (delegator start/end tx, validator registration, BLS PoP) are not duplicated into the anchor content. What the anchor uniquely holds is our operator identity, our assertion binding to the NodeID, our own observations, and hashes over our public artifacts.
3. **Anonymous pseudonymous continuity.** Identity is expressed as an `ed25519_pubkey_sha256_hex` fingerprint plus a `prev_anchor_root` chain — no legal identity is bound. Persistent operation is proven by the unbroken hash chain across anchors under the same key.
4. **Hyperion readability.** The A-chain memo scheme (below) is designed for standard Antelope Hyperion indexers so a third-party evaluator can query our full anchor timeline without any bespoke tooling.

## Schema summary (`schema_version: 1`)

Three branches under one top-level object. Each branch is hashed as sorted-key compact JSON; the three branch hashes concatenate (id ‖ ob ‖ ar) into one final SHA-256 = `dag_root_computed`.

### identity_branch (6 required fields)

| field | type | notes |
|---|---|---|
| `operator_ed25519_pubkey_sha256_hex` | 64-char hex | SHA-256 of the operator's ed25519 public key (raw 32 bytes) |
| `operator_asserts_node_id` | string | NodeID the operator asserts they operate (anonymous claim, not third-party-verifiable) |
| `prev_anchor_root` | 64-char hex or null | `dag_root_computed` of the immediately preceding anchor; null on genesis |
| `prev_anchor_tx` | XPR tx id or null | tx id of the prev anchor broadcast; null on genesis (ergonomic redundancy) |
| `key_seq` | integer ≥ 1 | operator identity key generation counter |
| `identity_history_root` | 64-char hex | SHA-256 Merkle root of `identity-history.jsonl` (full key rotation history) |

### observations_branch (8 required fields)

| field | type | notes |
|---|---|---|
| `cycle_number_observed` | integer ≥ 1 | Freedom Yield internal counter (no P-chain concept) |
| `cycle_start_time_observed` | ISO 8601 UTC | cycle startTime as observed via `platform.getCurrentValidators` |
| `cycle_end_time_observed` | ISO 8601 UTC or null | null while the cycle is open at anchor time |
| `self_stake_observed_metal` | number | human-readable METAL |
| `self_stake_observed_nmetal` | numeric string | P-chain canonical nMETAL, string to avoid JS precision loss |
| `fee_percent_observed_at_cycle_start` | number | delegation fee observed at cycle start; not a promise for the next cycle |
| `delegator_lifecycle_events_in_cycle_observed` | array | every started/ended event observed during the cycle (complete audit trail; hidden events impossible) |
| `delegator_snapshot_at_cycle_end` | array | remaining delegators at cycle end (or at anchor time if still open) |
| `evaluator_hints_declared_by_operator` | array of tag strings | optional; self-descriptor tags for subnet-evaluator discovery (e.g. `pseudonymous`, `single-operator`, `no-kyc-available`, `asia-region`). Declaration, not commitment |
| `subnet_targets_declared_by_operator` | array of subnet identifiers | optional; subnets the operator declares interest in serving. Empty = no explicit target |

Each element of `delegator_lifecycle_events_in_cycle_observed` has `event_type` (started or ended), `observed_at`, `delegator_tx_id`, `weight_nmetal`, and optionally `observed_end_time` (for started) or `actual_end_cause_observed` (for ended: duration_expiry, early_withdrawal, unknown).

### artifacts_branch (4 required fields)

| field | type | notes |
|---|---|---|
| `public_api_manifest_root` | 64-char hex | SHA-256 binary Merkle root of the sorted `public_api_files_hashed[].sha256` |
| `public_api_files_hashed` | array | one entry per anchored public API file, path lexicographically sorted |
| `period_uptime_observed_pct` | number | uptime observed from prev anchor to now (observation, not commitment) |
| `period_incident_count_observed` | integer | count of `Priority: high` or `Priority: urgent` notifications fired during the period |

## Merkle tree convention

Standard SHA-256 binary tree. Leaves = raw file bytes hashed with SHA-256. Leaf order = path lexicographic sort (canonical). Internal nodes = SHA-256 of the two child hex hashes concatenated. Odd leaf count: the last leaf is duplicated (Bitcoin convention). Single leaf: root = that leaf. Verifiers can reproduce this in any language.

## Dag root composition

```
identity_root      = sha256(JSON canonical form of identity_branch)      # 64-char hex
observations_root  = sha256(JSON canonical form of observations_branch)  # 64-char hex
artifacts_root     = sha256(JSON canonical form of artifacts_branch)     # 64-char hex

dag_root_computed  = sha256(identity_root ‖ observations_root ‖ artifacts_root)
```

**Concatenation semantics — normative:** the three per-branch roots are concatenated **as ASCII hex strings** (not as raw 32-byte binary values). That is, `sha256(id_root_hex_string || ob_root_hex_string || ar_root_hex_string)`, where `||` is byte concatenation of the 3×64 = **192 ASCII characters**. Verifiers who use `xxd -r -p` to convert each branch root to 32 raw bytes and then hash 96 raw bytes will get a **different** result — that is not the design.

Reference implementation (bash):
```sh
ID=$(jq -cS .identity_branch     "$file" | sha256sum | awk '{print $1}')  # 64 hex chars
OB=$(jq -cS .observations_branch "$file" | sha256sum | awk '{print $1}')
AR=$(jq -cS .artifacts_branch    "$file" | sha256sum | awk '{print $1}')
printf '%s%s%s' "$ID" "$OB" "$AR" | sha256sum | awk '{print $1}'         # dag_root_computed
```

The generator uses `jq -cS` (compact + sorted keys) for the JSON canonical form. **The exact bytes that get hashed are the `jq -cS` output including the trailing newline (`0x0a`) that `jq` appends by default** — the reference-implementation pipeline `jq -cS ... | sha256sum` carries that newline into the hash. Verifiers using RFC 8785, Python `json.dumps(sort_keys=True, separators=(',', ':'), ensure_ascii=False)`, JavaScript `JSON.stringify(sortDeep(...))`, or any other `jq -cS`-equivalent canonicalizer that emits the same sorted-key output **but omits the trailing newline** MUST append one byte (`0x0a`) before hashing. The three canonicalizers above produce byte-identical canonical strings; `sha256(canonical + "\n")` matches the on-chain memo hex, `sha256(canonical)` does not. See `tests/anchor-source-canonicalizer/test-canonicalizer-newline.sh` for a cross-canonicalizer regression check. The hex-string concat semantics is verified end-to-end against real testnet chain data on 2026-07-01 (memo 4 hex of tx `7b352b4a0b7c6202d14da51637c2a43791c1438d85ef43d7b7b45f17559839ea` matches the recomputed dag_root byte-for-byte).

## A-chain broadcast: HC-single 4-action pack

One P-chain-side EOSIO transaction. Four `eosio.token::transfer` actions from `freedomyield@anchor` to a separate sink account (BLOCK-1 forbids self-transfer). Memo prefix scheme is Hyperion-filterable:

```
tx (single Antelope transaction):
  action 1: memo = "fya1c<cycle>-id:<identity_root_hex>"
  action 2: memo = "fya1c<cycle>-ob:<observations_root_hex>"
  action 3: memo = "fya1c<cycle>-ar:<artifacts_root_hex>"
  action 4: memo = "fya1c<cycle>:<dag_root_computed_hex>"
```

`fyid` = Freedom Yield identity; `1` = anchor schema major; `v1` = schema version; `c<cycle>` = cycle number; suffix (`-id`, `-ob`, `-ar`, or absent = summary) picks the branch.

Hyperion queries:

```
# all our anchors
GET /v2/history/get_actions?account=freedomyield

# all anchors filtered to schema v1
GET /v2/history/get_actions?account=eosio.token&filter=eosio.token:transfer&data.memo=fya1c*

# cycle 3 anchor, all 4 actions
GET /v2/history/get_actions?account=eosio.token&filter=eosio.token:transfer&data.memo=fya1c3-*
```

## Reproducer commands (= third-party verification)

Any evaluator can reproduce the `dag_root_computed` from the runtime `anchor-source.json` alone:

```sh
# 1. Fetch the source
curl -sS https://metal.freedom-yield.com/api/anchor-source.json -o /tmp/anchor-source.json

# 2. Reproduce each branch root
jq -cS .identity_branch     /tmp/anchor-source.json | sha256sum | awk '{print $1}' > /tmp/id-root
jq -cS .observations_branch /tmp/anchor-source.json | sha256sum | awk '{print $1}' > /tmp/ob-root
jq -cS .artifacts_branch    /tmp/anchor-source.json | sha256sum | awk '{print $1}' > /tmp/ar-root

# 3. Compose the dag root
printf '%s%s%s' "$(cat /tmp/id-root)" "$(cat /tmp/ob-root)" "$(cat /tmp/ar-root)" | \
  sha256sum | awk '{print $1}'

# 4. Compare
jq -r .dag_root_computed /tmp/anchor-source.json
```

The output of steps 3 and 4 must be byte-identical.

To verify the `public_api_manifest_root`:

```sh
# For each entry in public_api_files_hashed, fetch the file and check its sha256
for pair in $(jq -c '.artifacts_branch.public_api_files_hashed[]' /tmp/anchor-source.json); do
  path=$(echo "$pair"  | jq -r .path)
  claimed=$(echo "$pair" | jq -r .sha256)
  actual=$(curl -sS "https://metal.freedom-yield.com/api/$path" | sha256sum | awk '{print $1}')
  [ "$claimed" = "$actual" ] && echo "OK  $path" || echo "FAIL $path (claimed=$claimed actual=$actual)"
done
```

Then reproduce the Merkle root over the SHA-256 leaves (lexicographic sort, binary tree, odd-leaf duplication). Any conforming Merkle implementation yields the same `public_api_manifest_root`.

## On-chain memo cross-check (= published source ↔ A-chain)

The step above proves the published file is internally consistent (its branch roots compose its own `dag_root_computed`). This step closes the loop: it proves the same recomputed roots equal the four memos actually inscribed on Metal A-chain, so the published source is the genuine signed pre-image of the on-chain anchor.

The four memos for schema major `1`, cycle `<N>` (= `fya1c<N>` — read `fya<S>c<N>` generically, `<S>` = schema major) are:

```
fya1c<N>-id:<identity_root_hex>       # action 1
fya1c<N>-ob:<observations_root_hex>   # action 2
fya1c<N>-ar:<artifacts_root_hex>      # action 3
fya1c<N>:<dag_root_computed_hex>      # action 4 (summary, no branch suffix)
```

Recompute the three branch roots and the combined root from the published source, then compare each against the corresponding memo suffix. The canonicalizer rules are identical to [Dag root composition](#dag-root-composition) above: `jq -cS` sorted-key compact JSON, the trailing `0x0a` newline is part of the hashed bytes, and the three roots concatenate as **ASCII hex strings** (192 characters), not as raw bytes.

```sh
# 0. Fetch the published source and pick the cycle number
curl -sS https://metal.freedom-yield.com/api/anchor-source.json -o /tmp/anchor-source.json
N=$(jq -r .observations_branch.cycle_number_observed /tmp/anchor-source.json)

# 1. Recompute the three branch roots + the combined dag root
ID=$(jq -cS .identity_branch     /tmp/anchor-source.json | sha256sum | awk '{print $1}')
OB=$(jq -cS .observations_branch /tmp/anchor-source.json | sha256sum | awk '{print $1}')
AR=$(jq -cS .artifacts_branch    /tmp/anchor-source.json | sha256sum | awk '{print $1}')
DAG=$(printf '%s%s%s' "$ID" "$OB" "$AR" | sha256sum | awk '{print $1}')

# 2. Fetch the four on-chain memos for this cycle via any Hyperion indexer
#    (account=eosio.token, filter=eosio.token:transfer, data.memo=fya1c${N}-*
#    and fya1c${N}:*). Extract the hex after each memo prefix, then:
#    memo "fya1c${N}-id:<hex>" hex  MUST equal  $ID
#    memo "fya1c${N}-ob:<hex>" hex  MUST equal  $OB
#    memo "fya1c${N}-ar:<hex>" hex  MUST equal  $AR
#    memo "fya1c${N}:<hex>"    hex  MUST equal  $DAG
```

All four equalities holding means the published `anchor-source.json` is the exact pre-image of the anchor recorded on chain. Any mismatch means the published source was altered after signing (or points at the wrong cycle) and MUST be treated as unverified. See the Hyperion query forms in [A-chain broadcast: HC-single 4-action pack](#a-chain-broadcast-hc-single-4-action-pack) for the exact `get_actions` calls.

## Generator (`scripts/gen-anchor-source.sh`)

```
gen-anchor-source.sh [--dry-run] [--out=path]

env overrides:
  NODE_ID, METALGO_API, ANOMALY_STATE_DIR, API_BASE_URL,
  VALIDATOR_JSON, IDENTITY_JSON, IDENTITY_HISTORY_JSONL,
  ANCHOR_HISTORY_JSONL, CYCLE_HISTORY_JSONL,
  UPTIME_HISTORY_JSONL, DELEGATOR_EVENTS_JSONL,
  ANOMALIES_LOG, OUT_FILE, SCHEMA_FILE

exit codes:
  0  success
  2  bad arg / usage error
  3  required input file missing
  4  P-chain RPC failed or NodeID not present in current validators
  5  obligation verb detected in output (verb discipline violation)
  6  schema validation failed
  7  atomic write failed
```

The generator prefers HTTPS fetch from `API_BASE_URL` (default: production public URL) for public-artifact hashing so what is anchored is exactly what an evaluator would fetch. Local repo files serve as offline / air-gapped fallback. Observation fields (`period_uptime_observed_pct`, `period_incident_count_observed`) come from the validator host state files. Identity fields come from operator-local files. Cycle boundaries and delegator snapshot come from Metal P-chain RPC.
