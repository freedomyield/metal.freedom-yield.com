# Metal Validator Toolkit

A grab-bag of small Bash and Python scripts we use to operate our Metal Blockchain validator (mainnet `NodeID-yyPvtQHTA4FZU5cJtjWZa7RVBpWU3i5v`). Everything in `scripts/` is committed to this public repo so other Metal validators — can fork what's useful, ignore what isn't.

There's no installer, no Docker image, no SaaS. Just shell scripts that the operator runs on their own node. Some are turnkey; some assume our specific two-host topology and need adaptation. The list below is honest about which is which.

## What this is not

- **Not a product**. No SLA, no support, no roadmap.
- **Not curated**. Anything the operator writes for their own node lives here. If a script is useful to others, it's a side benefit.
- **Not opinionated about your stack**. Bash + jq + cron + ntfy is what we use because it's boring and survives. Use whatever else suits you.

## What problem this solves

Running a Metal validator is mostly waiting. The hard part is noticing when something quietly stops working — a stuck push pipeline, a missed renewal window, slow peer count drift, a fee-market shift you didn't catch. These scripts mechanize the noticing.

For the data side, we also publish daily-sampled time-series of the wider Metal validator set (gini, fee market percentiles, peer turnover, full daily snapshots) at [`/data/`](https://metal.freedom-yield.com/data/). Those JSON / JSONL feeds are generated by the same scripts below.

## Tier 1 — Core reusable scripts

Pure chain-level operations. Point them at your local `metalgo` HTTP API and your NodeID, and they work. No assumptions about your hosting topology.

### `scripts/node-info.sh`
**Purpose:** Query the running `metalgo` HTTP API and write a human-readable `public/api/validator.json` (NodeID, bootstrap, uptime, stake, delegation fee, period bounds, total network validator count).
**Dependencies:** `curl`, `jq`, `bc`. A running `metalgo` reachable at `${METALGO_API:-http://localhost:9650}`.
**Env:** `METALGO_API` (default `http://localhost:9650`), `OWN_NODE_ID` (auto-detected via `info.getNodeID` if unset).
**Cron:** every 5 minutes.

### `scripts/gen-evidence.sh`
**Purpose:** Build a machine-readable evidence manifest (`public/api/evidence.json`) for institutional readers. Combines live state from `validator.json` with static project commitments and public-page URLs into a single self-describing JSON.
**Dependencies:** `jq`. Reads `public/api/validator.json`.
**Cron:** daily.

### `scripts/peer-validators.sh`
**Purpose:** Snapshot the full Metal validator set from your local `metalgo`'s P-Chain RPC into `public/api/peers.json`. Includes per-validator rows + network summary + operator clusters (NodeIDs sharing the same reward owner).
**Dependencies:** `curl`, `jq`.
**Env:** `METALGO_API`, `OUT` (default `public/api/peers.json`), `OWN_NODE_ID`.
**Cron:** daily (output ~100 KB).

### `scripts/peer-analytics.py`
**Purpose:** Companion to `peer-validators.sh`. Reads the fresh `peers.json` and emits derived artefacts: validator-set diff vs. last snapshot (`peers-changes.json`), Gini + top-10 + Metallicus share time-series preview (`peers-gini.json`) + full history mirror (`peers-gini-history.jsonl`), fee-market percentiles (`fee-market.json` + `fee-market-history.jsonl`).
**Dependencies:** Python 3.8+, no external libraries.
**Env:** `PEERS_JSON`, `NAMES_JSON`, `STATE_DIR`, `OUT_CHANGES`, `OUT_GINI`, `GEN_ISO` (all set by the shell wrapper that invokes it).
**Cron:** daily, right after `peer-validators.sh`.

### `scripts/check-validator.sh`
**Purpose:** Lightweight liveness check of your validator's presence in `getCurrentValidators` and its uptime number. Returns non-zero if your NodeID is missing or uptime drops below threshold. Suitable for cron or external monitoring.
**Dependencies:** `curl`, `jq`.
**Env:** `METALGO_API`, `OWN_NODE_ID`, `UPTIME_THRESHOLD` (default 80).

### `scripts/check-validator-period.sh`
**Purpose:** Daily check of the remaining time on your current validation period. Logs to a configurable log path. Pair with `notify.sh` for T-14/7/3/1 day alerts.
**Dependencies:** `curl`, `jq`.

### `scripts/uptime-history.sh`
**Purpose:** Long-horizon uptime track record. Appends daily samples to a master JSONL (keep-forever). Regenerates `public/api/uptime-recent.json` (last 90 days) and `public/api/uptime-cycles.json` (per-cycle summaries on cycle close, with `period_id` + explorer URL for audit).
**Dependencies:** `curl`, `jq`. Read-only access to `validator.json`.
**Cron:** daily, off-peak.

### `scripts/node-health-daily.sh`
**Purpose:** Once-a-day snapshot of host + `metalgo` health, kept forever. Master JSONL on the validator host (includes load, CPU, RAM, disk for ops use), plus a sanitized public subset (peer count, chain heights, bootstrap, container status) suitable for publication.
**Dependencies:** `curl`, `jq`, `docker` (for container status).

### `scripts/gen-renewal-ics.sh`
**Purpose:** Generate an iCalendar feed of your upcoming renewal events from `validator.json`'s `endTime`. Subscribable in Google / Apple Calendar. Token-named file URL provides obscurity without auth.
**Dependencies:** `jq`. Optional: a stable random token in a configurable token file.
**Cron:** daily, regenerate so it stays current.

### `scripts/dr-drill.sh`
**Purpose:** End-to-end disaster-recovery exercise on a Mac (or any second host). Decrypts the encrypted staker key backup, verifies SHA-256, boots a local-network `metalgo` with the restored keys, confirms `info.getNodeID` matches your production NodeID, cleans up. **Never** connects to mainnet — uses `--network-id=local`. Safe to run while production is up.
**Dependencies:** `docker`, `openssl`, `tar`, `sha256sum`, `jq`.
**Frequency:** periodically; untested backups aren't backups.

## Tier 2 — Reusable with assumptions

Useful but assume ntfy.sh push notifications and a few env conventions. Adapt the bits that don't fit.

### `scripts/notify.sh`
**Purpose:** Push a single ntfy.sh notification. Reads topic from a file (treated as a shared secret — anyone who knows it can publish/subscribe). Used by every alert pipeline below.
**Dependencies:** `curl`.
**Env:** `NTFY_TOPIC_FILE` (path to a file holding the topic identifier — set this), `NTFY_SERVER` (default `https://ntfy.sh`).
**Usage:** `bash notify.sh <priority> <title> <message...>`.
**Adapt:** If you don't use ntfy, swap with your own push (Slack webhook, Telegram bot, Pushover etc.) — the calling scripts just exec this one wrapper.

### `scripts/daily-status.sh`
**Purpose:** Daily digest composer. Pushes a single notification at one of three slots (`morning` / `evening` / `night`) summarizing validator + host state.
**Dependencies:** `notify.sh`, `jq`, optionally `public/api/server-status.json` for host metrics.
**Env:** `METALGO_RPC`, `WALLET_CONFIG` (optional — for wallet balance push, see below).

### `scripts/check-anomalies.sh`
**Purpose:** Anomaly detector. Runs frequently via cron. Compares current state vs. a state file to dedup notifications. Detection rules: container status, disk > 85%, memory > 95%, peer count < 10, validator missing from `getCurrentValidators`, period T-7 / T-3 / T-1, stale public `validator.json` push.
**Dependencies:** `notify.sh`, `jq`, `curl`. State file in a configurable path.

### `scripts/peer-geo.py`
**Purpose:** Resolve peer IPs from `info.peers` to country/city via `ip-api.com` (free tier, HTTP for non-authenticated calls). Writes `public/api/peer-geo.json` (NodeID + lat/lng + country/city, no IPs exposed). Used by the world map on the home page.
**Dependencies:** Python 3.8+, no external libraries. The free ip-api endpoint has a per-IP rate limit — TTL-cache aggressively. Our implementation caches 30 min per IP.
**Cron:** every ~30 minutes.

## Tier 3 — Operator-specific (reference only)

These reflect our specific two-host topology and our specific initial VPS setup. Useful as patterns; not turnkey.

| Script | What it does | Why it's specific |
|---|---|---|
| `scripts/push-to-web-host.sh` | SSH push of public JSON files from validator host → web host | Tied to our forced-command SSH wrapper and web-host path layout |
| `scripts/sync-to-validator-host.sh` | local Mac → validator host sync of `scripts/` + cron files | Specific to our deploy authorization model |
| `scripts/server-status.sh` | Host metrics JSON for ops dashboard | Tied to our `/ops/` page schema |
| `scripts/vps-bootstrap.sh` | Initial VPS setup (sshd hardening, fail2ban, docker, cron seeding) | Specific to our chosen base image |
| `scripts/security-audit.sh` | Periodic security posture check | Specific to our threat model |

## Cron pattern we use

One file per logical pipeline, kept readable. Roughly:

```cron
# Push to web frequently
*/5 * * * * root /path/to/scripts/node-info.sh && /path/to/scripts/push-to-web-host.sh

# Anomaly detection frequently
*/5 * * * * root /path/to/scripts/check-anomalies.sh

# Daily status digests at multiple times per day
# (operator's chosen times)

# Validator-set snapshot + analytics + history (daily)
0 4 * * * root /path/to/scripts/peer-validators.sh && /path/to/scripts/peer-analytics.py && /path/to/scripts/push-to-web-host.sh

# Uptime + node-health history (daily, off-peak)
30 0 * * * root /path/to/scripts/uptime-history.sh
35 0 * * * root /path/to/scripts/node-health-daily.sh

# Renewal calendar (rebuild daily, stays current)
10 0 * * * root /path/to/scripts/gen-renewal-ics.sh && /path/to/scripts/push-to-web-host.sh
```

The exact times are mostly arbitrary; spread them out so the push pipeline doesn't try to send 8 files in the same second.

## What's intentionally not here

- **Slashing protection / signer infra**. Metal Blockchain has no slashing, so we don't need Web3Signer / Dirk / Vouch. If/when slashing arrives, add it.
- **MEV smoothing**. Avalanche-family consensus doesn't expose MEV the way Ethereum builders do.
- **Liquid staking primitives**. Out of scope for a delegation-only operator.
- **Subnet validator tooling**. Will add once subnet deployments actually appear.

## Adapting for your own node

The bare minimum to get started:

1. Clone the repo, copy `scripts/` to your validator host. Pick an install path; edit cron accordingly.
2. Install ntfy (or replace `notify.sh` with your push of choice). Put the topic in a file and point `NTFY_TOPIC_FILE` at it.
3. Make sure `metalgo` is reachable at `http://localhost:9650` (or set `METALGO_API`).
4. Drop one of the cron lines from above to validate the pipeline before adding more.
5. The `public/api/` JSON files generated by these scripts are designed to be served by any static file server — Caddy, nginx, S3, GitHub Pages, your choice.

If you fork any of this and find a bug or have an obvious improvement, a PR or issue at this repo is welcome. We don't run a community channel; the code itself is the medium.
